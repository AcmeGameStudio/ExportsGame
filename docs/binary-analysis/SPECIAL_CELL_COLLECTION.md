## 糖果机与糖果格（53 / 54）

机器和糖果格从 `AdditionalParam` 解出相同结构 `CandyCellStateData { Id }`。糖果格的 Cost 表示它还能容纳的糖果数。机器初始化从全盘找状态 54，取其状态对象，筛选同 ID，按它与机器的三维欧氏距离升序排序。并列保留原枚举顺序。排序后的第一格用于计算机器朝向。机器向每个绑定的糖果格注册自身作为反馈监听器，邻格消除发生在糖果格旁时仅让对应机器播放摇晃，普通生产仍由机器自己的邻格消除推动。

设 `total = sum(绑定糖果格.Cost)`。机器的初始运行时 Cost 设为奇数 1、偶数 2，动画另持有 `total`。机器每次命中要求自身 Cost 大于零，忽略消除颜色与块数。它取绑定列表的**最后一格**，将该格 Cost 减 1，机器 Cost 写成 `3 - Cost`，调用 `ItemCollected(53)` 加 1，播放一颗糖果离开机器的动画。因而实际消耗从较远格开始，某格耗尽前继续用它。机器 Cost 的 1 和 2 会来回切换，反映表现进度。这个协程没有命中 FIFO，常规路径在首次让出执行前就更新 Cost 和目标；最终退场的延迟协程有独立清理。

糖果格恰好减到零时从机器列表移除。格子先锁 0.8 秒，写 Open 到当前配置并同步运行时格数据，延迟到期强制解锁并重建状态。最后一个糖果格移除时，机器 Cost 置零，锁 1.4 秒并写 Open、同步运行时数据，等 1 秒播放完成动画。动画尾部处理表现对象销毁，普通糖果飞行回调刷新目标 50。道具调用机器的同一命中路径，糖果格没有单独收集道具入口。教学使用独立 `FtueUse` 和退场协程。初始化用 `get_Item(0)`，关卡配置需要同 ID 的对应糖果格。

例：两个同 ID 糖果格的 Cost 分别是近处 1、远处 2。三次命中依次消耗远处、远处、近处，二次后远处开放，第三次后机器和近处都开放。

证据：初始化及顺序 0x2116820、0x21178d0、0x21178fc、0x2116e80–0x2116e9c；邻格反馈 0x2115c2c、0x2117758；命中和道具 0x2117698、0x2116f88、0x2116fb4；协程和退场 0x21179c4–0x2117d44；糖果格开放 0x2115a3c、0x2115cd4；动画回调 0x2118324、0x2118450、0x2118238。

## 双格橱柜（38 / 39）

主格保存并恢复 `CupboardCellStateData { CupboardId, DoorOpen }`，用同一个 ID 配对副格。主格初始化协程先记录 `Cost == 1` 的转移标志、等待一帧，再从全盘取第一个同 ID 的 39。主格把自身监听器交给副格，副格保存 `自身邻格索引 − 主格邻格索引`，因此两格共有的邻格只由主格处理。副格 Cost 也是杯子进度的一部分。柜体显示跨越二格，杯子显示数从二格 Cost 恢复，已开门状态也从存档恢复。

两格都订阅全局消除。主格检查相邻，副格还检查上述独有邻格表。第一次有效命中时，门从关到开，写回 `DoorOpen` 并播放脱门动画，这次没有收杯。之后每次有效命中进入 `UpdateCostAndAnimate(true)`。颜色和消除块数均不参与判断。

- 各格的已耗尽哨兵是 **Cost 1**，不是零。命中时计算 `next = Cost - 1`，实际写入 `max(1, next)`，并记住这次是否从 1 算到 0。
- 本侧还有杯子时，主格直接计 1 并播放本侧杯子动画。副格通过主格的 `AnimateCup` 计 1，按副格侧的索引选择表现。
- 本侧已经是 Cost 1 时，有转移权限的命中只传给另一侧一次，传入 `false` 防止二次转发。道具命中复用开门或收杯的入口。一般可用性看本侧 Cost 是否大于 1，普通入口允许有剩余杯子的配对格承接。另有针对道具枚举值 3 的可用性分支，见下列 RVA。
- 杯子动画完成时刷新目标 36，检查两侧是否均已到 Cost 1。完成则主、副格注销监听，将 Cost 归零，写 Open 并重建。主格锁 1 秒，0.5 秒后播放碎柜效果并强制解锁。退场由杯子回调发起。

例：主格 Cost 3、副格 Cost 2。共用邻格的消除第一次打开门，此后主格两次收杯到 Cost 1。下一次从主格到达的有效命中转给副格，副格收最后一杯，完成回调开放二格。

## 骰子（44）

每个实例构造函数都会以 `max(0, GetRequiredForCellState(44))` 重写类共享的 `RemainingDiceGoal`（不是只执行一次的静态初始化）；正常关卡若只有一个骰子时才等价于一次初始化。随后从 `AdditionalParam` 恢复 `DiceStateData { PendingHits, LastDiceValue, PendingDiceValue }`。如果恢复时目标仍有效，注册目标结束事件。恢复中已经决定的骰面 `PendingDiceValue` 保留，再为每个 `PendingHits` 重新掷一次，直接把总和记到目标并扣共享剩余值，因此不会把这些命中再额外扣一次。存档把队列和未入账骰面置零，保存末次用于显示的面，随后更新骰面朝向。初始化时目标已清空则隐藏骰子。

普通邻格消除和道具命中均要求共享剩余目标大于零，进入 `OnDiceHit`，颜色、块数均不参与。每次有效调用先将 `PendingHits` 加 1 并保存，仅在没有活动协程时启动一条。协程先等一帧，再执行：

1. 从整数 `Random.Range(1, 7)` 取骰面，取出一个命中，将骰面同时保存为 `LastDiceValue` 和 `PendingDiceValue`。
2. 播放投掷和数字收集表现，等 1.7 秒后调用 `ItemCollected(44, diceValue)`。共享剩余量按 `max(0, remaining - diceValue)` 更新。
3. 只要有待处理命中且目标尚有剩余，就继续掷。退出时把 `PendingDiceValue` 清零保存，清协程引用。共享目标变成零时播放隐藏骰子的完成动画。已收到的多余 `PendingHits` 在这条完成路径中没有逐个改写为零。

道具可用性还要求本骰子没有正在运行的协程，邻格命中仍可排队。骰子完成只隐藏表现，没有把格子重建为 Open。教学专用方法先演示 3，再演示 5，直接调用表现方法。

## 螺母发生器（33）

螺杆从 `AdditionalParam` 的 `GeneratorNutsStateData.HexTypes` 恢复颜色序列；空数据时按表现配置里的螺母槽数填满。保存序列不足时补随机颜色。初始化把 `CellData.Probability` 作为颜色变化上限，教学路径用 3。随机配色从材质可用色取候选，要求颜色非零、不在当前螺杆上，且 `HexTypes.IntFromType(color) < min(variationLimit, MaxTypesInTray)`。从候选随机取一色。若为空，改为从现存螺母列表的末尾至多三个随机取色，允许重复。动画中新补的螺母重新使用这一规则。

全局消除须满足对应目标 33 尚未完成、消除源相邻、本格未临时锁。每次消除只看颜色，从螺母列表尾部向索引零扫描，找首个同色且索引大于当前 `_animatingObjects` 的螺母；命中即把该索引写成 `_animatingObjects`。这一值从 -1 起步。当设为 2 时锁格 3 秒。调用 `CollectNut` 时按 `_animatingObjects + 1` 遍历收集次数，每次先检查目标是否已经完成，再为状态 33 登记一个。可见移出的是出口到目标色之间的整段，颜色只决定段长。同色块消除 10 还是 20 不改变这段长度。

螺母退出协程一次从列表头取一个，旋松、移除并飞向目标，在动画进行中逐次缩小待处理索引。货量变化通过保存回调序列化。目标仍需要螺母时，飞行动画结束会复用表现对象，随机取新颜色补到列表尾，保存、刷新目标并触发重检。目标已完成时广播本机关类的结束事件，各实例注销监听，清理/保存颜色，再让剩余螺母退场。观察到的是关停表现，没有把 33 切为 Open。

## 花苞（36）

介绍状态由 Cost 和 RequiredType 保存。Cost 2 表示未选色；已有非零 RequiredType 的初始化会按该颜色打开花苞。监听全局消除并自行检查相邻。Cost 为 2 时，记录每次相邻消除的颜色和源格世界坐标，只启动一条协程，把同一帧内的候选聚在一起。等待一帧后按颜色分组，按每组**事件条数**降序，组内保持源事件顺序，并列的首组是最先出现的颜色。将分组展开后：

- 若前两条颜色相同，一次播开花加收集，登记一个 Bloom。这要求同批次同色消除至少两次。
- 否则扣 1 Cost，写首条颜色到 RequiredType，播放从第一条所在格飞来的颜色滴。之后只有相同颜色的邻格消除才会收花，单次消除块数始终无关。

例：同一批按事件顺序消除蓝 10、红 12、蓝 11，会以蓝色直接开花并收集。如果只有蓝 10、红 12，则先开为蓝花并留在棋盘，后续相邻蓝色消除才收集。

收集立即注销监听、登记 1、锁格并清 Cost 和 RequiredType，写 Open 并重建。表现回调再更新目标 35、触发排序重检并移除花表现。道具打未开的 Cost 2 花苞时，随机从托盘可用的颜色索引范围取色，进入 Cost 1；打 Cost 1 的已开花直接收集。教学演示独立，停止普通监听。

证据：初始化 0x210ebc4；触发和颜色比较 0x2110240、0x2110384；合批、排序和判断 0x2110724–0x2110d64，键和组大小 0x21106c8、0x21106d0；收集开放 0x210f710；表现回调 0x2111234、0x2111320；道具 0x210eff4、0x210f13c。

## 爆米花机与爆米花（47 / 48）

机器把剩余计数保存为当前 Cost，`PopcornMakerStateData.MaxCounterValue` 保存动画条的原始上限，初次以 Cost 填入。Cost 为正时生成表现并监听全局消除。处理器没有邻接检查，任意格的正常顶部消除都按**实际消除的块数**扣，`Cost = max(0, Cost - count)`。到零注销监听。单条协程先等一帧，再把当前 Cost 交给机器表现。表现等待后若 Cost 又变了，则按更新后的值继续一轮。Cost 最终为零时开始投放。初进或读档时已为零的机器直接执行投放结算，不重播跳跃过程。

投放计算从全盘调用 `PopcornMakerProperties.FilterInteractableCells` 的继承实现，排除临时锁、全局锁、可按 10 块消除的格，依配置检查可交互和排除状态列表、占用和车顶色条件。之后先 `Shuffle`，再按目标格 Cost 升序，等 Cost 的顺序由洗牌决定。令 `N` 为过滤后的数量，最多取 `min(N - 1, 3)` 个，给合格集合留一个空缺；候选不足的数量会直接记目标。

每个目标写 `Popcorn(48, Cost=1)`，把原当前配置保留为后继状态。子格的 `AdditionalParam` 包括 `IsJumpPending`、`StartPosition`（机器坐标）、`CupRotation`。正常播放时先锁目标 0.4 秒，再重建并播放落杯。读档时按保存数据设置杯子、旋转和未播动画，后继草地用草基底显示。未投到棋盘的部分调用 `ItemCollected(48, 3 - placedCount)`。如两格可选，则投 1 杯，并直接收 2 杯。机器改 Open 并重建；普通动画路径也短锁机器 0.4 秒。

杯子响应邻格消除或道具，不比较颜色或块数。Cost 小于 1 时返回；有效时立即置零，记 1 杯并播放收集，锁格 0.4 秒、应用后继配置再重建。落杯回调更新介绍/棋盘排序，收集回调销毁表现。48 还实现播种袋的显草接口。机器没有单独覆盖道具收集方法，教学脚本直接驱动计数和投放表现。

## 特斯拉塔与灯泡（49 / 50）

塔以 Cost 记录充电阶段，Cost 1 表示已充电，2 表示等待充电。初始化时若全关灯泡目标 47 已完成，塔直接标记完成。否则从全盘经塔配置的 `FilterCellsWithOption` 找候选，保留 Cost 大于零的格，取灯泡状态对象。这里使用允许和排除状态、占用块、车顶等配置，调用时三个临时过滤开关（临时锁、全局锁、可消除）均为 false。灯泡按 Cost 分组，组键升序，组内按随机键升序。取灯时从列表头移除条目，重新检查其当前状态 50 且 Cost 大于零，不合格的继续跳过。多塔可以持有重叠候选，实际消耗后要靠这次复核防重复。

每次相邻消除入队 1，颜色和消除块数均不参与。单一协程逐个处理：

1. Cost 为 2 时改为 1，播放充电，等待 1.5 秒。
2. 另一阶段时把 Cost 设回 2，找下一颗可用灯泡。找到则立即调用其 `TurnOnAndCollect(false, false)`，同时播放塔放电，等待 1.2 秒后继续队列。找不到则关停。
3. 塔收到全关目标 47 完成事件也关停，将待处理命中清零、注销监听并切到关停表现。未观察到塔在这个流程被改成 Open。

灯泡的常规 `TurnOnAndCollect(false, false)` 协程有两段明确时序：先把自身 Cost 写为 0，经 `ICellStateContext` slot 20 调用 `LockCellForSeconds(1.5)`，再等待常量 1.2 秒；恢复后启动 `BulbOnCoroutine`，非 FTUE 路径立即以当前状态 50 调用 `ItemCollected(50, 1)`，随后再次经 slot 20 锁 1.0 秒，经 slot 28 `ChangeCellDataToOpenState`，最后经无参 slot 25 `StateReAssign`。`skipDelay=true`（入场时 Cost 已为零的补结算路径）跳过首段 1.5 秒锁和 1.2 秒等待，直接进入点亮/收尾段。该灯泡路径没有调用 slot 21 `ForceUnlockCell`，不能把后续 `blr` 误写成强制解锁。塔侧放电也独立等待 1.2 秒。`BulbOnCoroutine` 自身先播放点亮动画，再等待 0.5 秒进入后续飞行/收尾序列；`OnAnimationComplete` 回调刷新目标 47 并移除旧模型。塔支持道具，与邻格命中共用队列；灯泡没有单独覆盖道具入口。教学由塔指定目标并传教学标志，不走普通收集结算。

## 烤面包机（14）

机器的 Cost 在 2 和 1 间切换。构造和初始化恢复 `ToasterStateData { PendingCollectCalls }`，用于保存已产生、待入账的吐司片数。进关初始化若有待补数量，直接按该数提交目标、刷新目标 17 并清零保存。若目标已完成，则停用反馈。普通路径订阅全局消除并检查邻接，只计一次命中，颜色和单次消除块数无关。

每个有效命中先检查全关目标 17 未完成，更新 `Cost = 3 - oldCost`，并向表现队列加一笔。如旧 Cost 为 1，这笔构成一对命中的第二笔，立即将 `PendingCollectCalls` 加 2 并保存。一个表现协程按队列依次运行上料、烹烤、吐司起跳飞行。播放到吐司收集回调才调用 `ItemCollected(14, 2)`、刷新目标 17、从保存待发数减 2。达到目标会广播烤面包机结束事件，各机器注销监听并显示结束态。机器状态保留为 14；没有观察到它在结束回调切 Open，也没有为排队过程调用临时锁。对它使用道具复用一次命中，教学入口先注销普通监听。

证据：初始化和恢复 0x218b724、0x218b890、0x218b9fc；全局注册与相邻 0x218af30、0x218bb64；命中与保存 0x218b138；表现入队及协程 0x218bc28、0x218c4e0、0x218c644；收集和退出 0x218bc84、0x218bdb0、0x218bdd0；道具 0x218b134、0x218b638、教学 0x218b2f0。

## 保险箱（42）

保险箱从当前 Cost 恢复剩余块数，以 60 为完整进度基准。初始化按 `(60 - Cost) / 60.0 * 360°` 恢复转盘；未用独立的机关 JSON 状态。订阅全局消除，要求本格 Cost 至少 1 且消除源相邻，忽略颜色并按消除块数推进。

每次先取现有 Cost。若将耗尽，就先锁本格，再写为零；其余直接相减。设置待动画标志，并在没有运行的协程时启动一条。协程先等一帧，每次取最新 Cost，把旋转推进到累计进度。动画播放期间的新命中只更新数据和标志，下一轮按最新值重播转盘。动画稳定且 Cost 为零时，播放开门，再播放金条飞向 HUD。收集动画完成才注销全局监听、调用 `ItemCollected(42)`、强制解锁、写 Open 并重建。视觉回调随后刷新目标 39 并触发棋盘重检。

道具相当于扣 10 块，Cost 大于零即可使用。教学入口注销普通监听后扣 20，教学开门传入空的收集结束回调。例：余 8 块时，相邻消除 12 块，会先锁箱、剩余置零，直到金条动画回调才开放格子。

证据：初始化与恢复角度 0x217976c、0x2179ee8；全局监听 0x2179660；触发与扣块 0x217a098、0x21799cc；协程 0x217a3fc；开门和金条链 0x217abc4、0x217b6f0、0x217b1d8、0x217b7f0；收集开放 0x217a270；道具与教学 0x21799c4、0x2179c4c、0x2179ecc。
