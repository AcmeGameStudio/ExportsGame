# Hexa Sort 6.2.20 移动机关的运行时行为

取证对象为同包 ARM64 IL2CPP 二进制与 v39 metadata。地址是 RVA。消除广播、邻格回调及批量移除的区别见 [消除事件与特殊格反应](SPECIAL_CELL_REACTIONS.md)。`Cost` 是格状态字段，`count` 是本次顶部色段消除块数。

## Penguin(60) 与 Igloo(61)

### 配对和路线

Penguin 的 `AdditionalParam` 反序列化为 `PenguinStateData(Id)`，Igloo 为 `IglooStateData(Id, Rotation)`。冰屋入口格是冰屋本格沿 `(Rotation + 3) % 6` 的相邻坐标。冰屋从经本机关互动配置筛过的棋盘取同 ID 的企鹅数作为 `_penguinsRemaining`。企鹅经自身互动配置筛棋盘，再取序列里第一个同 ID 的冰屋。两个过滤入口均将移除临时锁格、全局锁格、可消除格的选项置为 false，仍应用配置的状态规则。多个同 ID 冰屋没有额外距离排序。有效数据应给出可访问的门格和匹配对象。配置解析、门格索引和配对分别见 0x2152a70、0x2151b30、0x2152230–0x21522d8、0x21523d0–0x2152448、0x21549e0、0x2155918。

企鹅取世界空间的门格位置减自身位置，把向量转换到格的局部方向，平方长度至少约 `1e-12` 时，用 `atan2(x,z) × 180/π` 量化朝向。六方向转换将角度归一到一圈，除 60 后取最近整数，半值取偶数，再模 6。每一跳只取这个方向上的直接邻格。`CalculatePathAndPriority` 另沿同方向记录排序优先坐标，遇无效坐标、门格或首个非 Open/Grass 状态结束。有效的阻挡格先加入列表再停止。由近到远，分数从 9,765,625 先整除 5 再写第一个，之后每格继续整除 5。企鹅冻结时返回空优先字典，`Cost < 2` 才暴露该序列。此字典供排序器使用，移动仍逐格检查实时棋盘。见 0x2154be8、0x20ef018、0x215486c、0x2154d6c、0x21529e8。

### 解冻、移步和收集

- 专用邻格消除通知仅在 `Cost >= 2` 时进入 `Merge`。每次减 1 并以 1 为下限，启动企鹅解冻表现，转成 1 时恢复格面。颜色和 `count` 不进入判定。此时已经禁止道具命中，企鹅仍待移动。`CanUsePowerUpOfType` 同样只看 `Cost > 1`，实际使用和邻消共用扣减。冻结时是临时阻挡，解冻时状态自身返回全局锁。见 0x21529b0、0x21529cc、0x21538bc、0x21538d8、0x2153904、0x2155040。
- 初始化生成或接收企鹅表现后，协程先让一帧，再找冰屋、方向和下一格、计算优先、注册事件，随后可对已解冻且未走动的企鹅发起移动。之后落子、道具事件和排序重检事件都进 `CheckBoard`。它要求 `Cost <= 1`、表现仍存在且启用、没有在走、没有待执行检查协程。检查协程再让一帧并尝试锁下一格，执行后清协程引用。见 0x2152d38、0x2155ae4、0x2155680、0x215405c、0x2155bec。
- 下一格须为空堆且为 Open 或下层格，即 `Cell.IsClear`。尚未由本企鹅预锁时，还须未临时锁。成功锁下一格 3 秒并设自身 `_lockingCell`，让后续检查接受自己已占的临时锁。动画进到本格中心附近也会预锁再下一格，到门格时跳过预锁。长路径前方被挡时只停在当前格，无转向或绕路。见 0x21a3114、0x2155188、0x2155140、0x215506c。
- 离开一格时立即启动模型移动，目标运行时写 Penguin/Cost=1 并复制源 `AdditionalParam`。调用会先保存目标的现有配置为后继，再以同一企鹅表现重建目标状态，立即释放目标的临时锁。旧状态清模型引用、锁原格 1 秒并重新赋态。原格下方是 Grass 就提升后继，否则转 Open。移动动画结束对新所属状态再次执行移动决策，再请求排序重检。见 0x21541d8、0x21546a4、0x215437c、0x21562e4、0x2156328。
- 位于门格时进入冰屋动画。普通流程的入屋序列回调调用 `PenguinReachedIntoIgloo`，由冰屋剩余数减 1，播放收集，并以状态 60 提交一项目标，随后请求目标及排序刷新。剩余数恰好为 0 时冰屋播停用动画，未在该分支重建成 Open。门格上的企鹅按上面的 Grass/Open 分支清除。教程单独指定索引 3 的相邻目标并有独立的入屋动画，冰屋在教程分支通知脚本。见 0x21551e8、0x21552f8、0x215565c、0x21524b0、0x21525f0、0x2153168、0x2153b8c。

## Rabbit(62)

`AdditionalParam` 反序列化为 `RabbitStateData(ID, SequenceID)`。普通初始化从全盘按配置筛出可参照格，取其 Rabbit 状态并按 ID 分组。组内按 `SequenceID` 升序排列，最小序号所在格激活并生成兔子，各格将同组第一个序号严格更大的格存为下一站。此处没有要求物理相邻，也没有加一匹配或几何搜索。若数据给出重复最小序号，激活判断使用序号值相等，多个格都可能激活。下一站候选同序号时保留序列中的先者，未见第二排序键。见 0x2170b2c、0x2170d18、0x2171eec、0x2171f20、0x2172054。

- 活跃格报告为临时阻挡，可以接受道具。未激活格报告全局锁，忽略邻消和道具。普通专用邻消和 `PowerUpUsedOfType` 进入同一 `MergeDecision`，不读取颜色或 `count`。见 0x2170a94–0x2170ab0、0x2171a78、0x2171b44。
- 活跃格先保存 `Cost - 1`。结果恰为 1 时留下兔子，面向下一站播放唤醒。其余结果都走转移分支，先清源活跃标志，再从源传递模型给下一站。普通导出关卡中的 Rabbit 初始 Cost 均为 2。每个需要离开的站通常两次命中起跳，末站一收到兔子便自动完成，无须将末站 Cost 减到 0。代码没有一般化的「Cost 大于 1 一直等待」分支。见 0x2171a7c–0x2171b3c。
- 下一站的 `TransferRabbit` 在普通流程立即提交一次 `ItemCollected(62)`，再接管并重挂表现，播放跳跃。下一站仍有后续时，在跳跃完成回调才把该站设为活跃。兔子在空中期间，该站仍拒绝邻消和道具。源播放收土特效，锁约 1.4 秒并以 Open 重建。见 0x21717a0、0x2171cc4、0x217236c、0x217284c、0x2171f54、0x2171b48。
- 下一站无后续时，跳跃后播放入洞及收土，末格在启动最终序列时锁约 5.4 秒并以 Open 重建，不等下次消除。普通收土完成回调通知 Rabbit 目标 UI 并重检棋盘，该回调不直接再调用 `ItemCollected`。它在处理结束时销毁对应的表现对象。见 0x217187c–0x21718c8、0x2171d5c、0x2172648、0x21727bc、0x217287c。
- 教程单独将 Cost 2 的格激活，选教程列表中状态 62 且 Cost 1 的目标。教程使用入口直接扣减并传递 `isFtue=true`，抑制普通即时计分，收土回调改为通知教程脚本。见 0x217143c、0x2172074、0x21716e8、0x21717f8、0x2172684。

## Doll(29)

初始化以 `Cost - 1` 作为嵌套娃娃表现索引。`ParamOne` 控制启动延迟，正值再加 0.5 秒，本格锁定时间是该延迟再加 0.1 秒，表现激活回调主动解除锁。格数据的 `NextState == Grass` 及 `NextCost == 1` 分别控制底草是否显示和用哪种草色。种子袋也可通过 `ISeedBoxListener.EnableGrass` 更新底草。该状态的初始化和命中没有读入 Doll 专用 `AdditionalParam`。见 0x2126aa0、0x212a360、0x2127b68。

普通命中订阅 `Cell.Merged`，筛消除源相邻且本格未临时锁，再要求模型仍在且 `Cost >= 1`。命中颜色与块数未使用。道具直接走 `CanPlaceDoll` 和同一入队方法。普通入口还单独筛临时锁，道具处理器没有这一层，外部仍受格的道具准入规则约束。收到有效命中时 `_totalDollsPlaced++`，已有协程只累计。首个协程锁本格 1 秒并让一帧。每轮取累计值为 `mergesCount` 后清零，`mergesCount > 0` 时只减 **一次** Cost。其值传入原地弹跳表现；下一批异步积累另行处理。模型消失时会注销监听。见 0x2126d84、0x21271d8、0x2127200、0x21274c0、0x2127388、0x2127d80。

| 扣减结果 | 行为 |
|---|---|
| `newCost == 0` | 立即 `ItemCollected(29)` 并注销监听。有非 Open 后继时先启动 HUD 动画，再提升后继并重建格。无该后继时先 `ChangeState(Open)`，两次各等 0.5 秒，中间播打开动作，然后发 HUD 动画和延迟销毁表现。HUD 动画回调更新目标显示。见 0x2129588、0x212a4b4、0x212a590。 |
| `newCost > 0` 且有候选 | 从本格邻居中筛出 `(Open || IsLowerLayerState) && Blocks.Count==0 && !IsTemporaryLocked`，按随机索引取一格。源格播开启动作，等约 0.2 秒后播跳跃，再等约 1 秒。目标写入 `Doll(newCost, RequiredType=0, ParamOne=1)` 并重建，目标原配置保存为后继。源格重新赋态、提升后继并刷新，旧模型销毁。选中时暂未写锁或占用，目标的新 Doll 在重建时才执行初始化锁。见 0x21278b8、0x2127cf8、0x21280a4、0x2128170、0x21283a0–0x2128470。 |
| `newCost > 0` 且无候选 | Doll 留在原格，依次打开、弹跳、更新表现。等待约 0.5、0.3、0.5 秒，结束后请求重检，继续检查这段时间积累的新命中。见 0x212994c、0x2127e04–0x2127f54。 |

例如，同一次待处理阶段积累两次有效邻消且 `Cost=3`，本轮先清两个待处理计数，只将 Cost 变为 2。若这时无空邻格，会原地完成表现并在本轮之后检查新事件。教程使用显式目标和独立 `FtueAnimationCoroutine`，跳转后按教程目标和脚本参数控制场景及 HUD 回调。见 0x21273ec、0x2128bf0。

## SnakeBody(25)、SnakeTail(26) 与 SnakeHead 类

### 分组与轮廓

组 ID 来自 `CellData.Probability`，初始化后格的 `ParamOne` 保存同一值。普通构建找全盘相同 ID 的 Tail，取匹配列表的索引 0。这个尾格的 `AdditionalParam` 是十进制整数字符串，用于记录表现初始化的最大长度；`TryParse` 结果为 0 时，会用 `ceil(初始表现长度)` 回填运行时字段。长度公式为 `Cost == 0 ? 0 : factor × (Cost - 2) + initialFactor`，两个因子来自表现对象。见 0x2180c80、0x2181198、0x2180f98。

尾格起始写入表现的格列表。从当前段的 `Neighbours` 顺序里取第一个 `state==SnakeBody && ID相同 && Cost==当前段Cost-2` 的格，记录为折线控制点后递归。无匹配就停止。只剩尾格时使用首邻格生成一个额外表现控制点。这个过程用于绘制整条蛇，命中阶段不会沿这条折线遍历、逐个传播。见 0x2180fbc、0x2181558、0x2181730。

### 消除、道具与结束

- Body 和 Tail 都订阅全局 `Cell.Merged`。对每个监听器，检查的是**消除源的邻居列表里是否存在任意同组 SnakeBody/Tail**。命中一组时，即使某一段离消除源很远，其监听器也会减 Cost。邻居里有多段同组仍只触发该监听器一次。颜色与消除块数不参与。全局 `PowerUpApplied` 监听则要求被击中的格本身是 25/26 且与监听器同组，直接推进该组，无邻接要求。见 0x217e9d4、0x217ef1c、0x217f214、0x217f2fc、0x2180178、0x21805f8、0x2181270。
- Body 每次 `Cost--`。新 Cost 大于 0 时结束；小于等于 0 则约 0.1 秒后在回调设为 0、转 Open、重检棋盘并注销监听。`Execute` 未设单个待完成标志，回调前可能重复进入。Body 的结束没有独立提交 Snake 收集。见 0x217f094、0x217f3d8。
- Tail 旧 Cost <=0 时返回。旧 Cost 大于 2 时减 1，旧 Cost 为 1 或 2 时都直接归零，再把新值传入卷蛇表现。表现停止已有样条协程并从当前长度向新目标长度继续，单次新命中不会并排跑第二条样条。`newCost == 0` 时本格立即锁 1.5 秒、`ItemCollected(26)`、改配置为 Open 并刷新运行数据和注销监听。见 0x21802f0、0x2180060、0x2181840。
- 收到底后样条协程启动 HUD 王冠收集。HUD 回调触发蛇尾状态的重检钩子，解除临时锁、请求排序重检并重建格；另一个回调播放目标命中表现、更新目标视图后销毁表现。教程用首个 Body 构建教程表现，使用教程入口分别推进段和尾格的颜色无关动画，HUD 回调通知教程脚本。见 0x2182534、0x2181cd4、0x21806dc、0x2182298、0x21824a0、0x2180924、0x217ff60、0x21807f0。
- `SnakeHeadCellState` 类有初始化表现，其 `PowerUpUsed`、`ExecuteSnake`、`FtueUse` 和注册入口为直接返回。25、26 走 Body、Tail 处理器。未发现把 SnakeHead 作为一个受消除驱动的第三格状态的证据。见 0x217f504、0x217f540、0x217f544、0x217f81c–0x217f828。

## Drone(30)、DronePad(31) 与 DroneHandler(32)

### 配对、停靠点和存档恢复

31 是待用停机坪，30 是当前有无人机的停机坪，32 为末端接收器。组 ID 来自 `CellData.Probability`，搜索候选读运行时 `ParamOne`。31 构造时只设置格面，不自行响应消除。32 初始化约 0.3 秒后执行一次停靠点选择和表现初始化。见 0x212da58、0x212e9a0、0x2130a44、0x2132990。

`GetDronePad` 实际按下面的次序取值。无目标会给出空引用，飞行分支用 32 本格作为目的地。

1. 取全盘第一个 `state==30 && ParamOne==id && Cost!=0`。多个候选保留网格枚举顺序。
2. 否则从全盘取 `state==31 && ParamOne==id && Cost!=0`，按 Cost **升序**确定最小值，再随机取一个同最小 Cost 的格。
3. 有目标时，`UpdatedDroneHolder` 把该格配置转成状态 30 并用原配置重建，已有状态 30 则保留。无目标时，将 32 的 `_hasDrone` 设真。

筛选未要求空堆、邻接或临时锁，且无距离排序。已失去 Cost 的旧状态 30 即使暂未完成动画，也会被排除。初始化表现停在返回格的世界位置，并按同组、Cost 非零、状态介于 30–32 的格数生成携带块，取停靠点 Cost 的奇偶决定初始扇叶状态。没有返回格时，由 32 本格初始化一块携带表现。见 0x21304ac、0x2130ad4、0x2130b14、0x2130d40、0x2130d70、0x212f538、0x212f5f0、0x2130a8c。

### 命中阶段与动画回调

30 订阅全局消除，要求源相邻、`Cost >= 1`。32 同样要求相邻，并且 `_hasDrone` 为真和 Cost 非零才处理实际命中。二者均不读取颜色和消除块数。30 的道具准入要求未临时锁且 Cost 非零，32 还要求 `_hasDrone`。道具使用走同一扣减器。见 0x212e29c、0x212fb88、0x212e104、0x212f2d4、0x212dd44、0x212f090。

30 命中先 `newCost = Cost - 1`，写回 Cost。新值为奇数时广播 `OnDroneStateUpdated(1, id, callback)`，同 ID 的 32 播扇叶旋转。新值为偶数时，30 将 Cost 再置 0、锁本格 3.5 秒，并广播 `OnDroneStateUpdated(2, id, callback)`。因此正常偶数初始 Cost 的停机坪仍为两次命中起飞，即使初值为 4 或 6。这些较高初值还决定多个停机坪的选择顺序。见 0x212dd60–0x212dfdc、0x2130214。

同 ID 的 32 收到阶段 2 后选择下一个停靠点，目标为空则飞回本格。投下的携带块是 `DroneHex` 自有的表现块，投掷回调将它从携带列表移除。它不调用 `Cell.AddBlocks` 增加可排序颜色。飞行序列在配置的落块时点调用旧停靠点回调，旧点恢复格面、提升其后继、`ReInit`、解除临时锁并同步朝向。序列还请求重检。落到目标的回调才将新坪重建为 30，或将接收器 `_hasDrone` 设真。正常退出的原状态对象通过销毁注销监听。见 0x212e3d8、0x212dff8、0x2130d54、0x21310e0、0x21315a8–0x21315d4、0x2132618、0x213263c、0x2132880。

32 接管无人机后处理自身 Cost。先减 1，结果奇数时只转扇叶。结果偶数时立即置 0、把运行时 `ParamOne` 设为 -2、锁本格 3.5 秒，把模型挂到棋盘父节点并播最终飞离。最终落块回调在普通流程提交 `ItemCollected(30)`，恢复格面、提升 32 原有后继、重建并解锁。飞离完成再销毁表现、通知 Drone 的目标 UI 并重检。中间每次转移没有提交 Drone 的目标减一。教程跳过普通选坪，使用教程飞行表现，最终回调只恢复格面，教程计数由表现回调通知。见 0x212f0ac、0x212fc9c、0x212ff1c、0x212ffb4、0x213266c、0x2132688、0x212ed40。

例如，32 与两个 31 同组，后者分别 Cost 2、4。开局 Cost 2 的坪变 30。它两次有效命中从 2 到 1 再到 0，飞往 Cost 4 的坪。第二个坪两次有效命中从 4 到 3 再归零，飞回 32。32 自身的命中到达偶数归零分支后才提交收集。

## CarParking(17) 与 Car 块(0x100)

### 固定车道

17 是停车位格，Car 是 `HexType=256` 的块。普通初始化没有读取本机关专用 `AdditionalParam`。车道从停车位开始反向扫描，方向用停车位的 Cost 直接索引 `HexFlatTop.Neighbours`。这个列表的世界平面偏移按索引 0–5 为 `(0,1.9)`、`(0,-1.9)`、`(-1.6454,0.95)`、`(1.6454,0.95)`、`(-1.6454,-0.95)`、`(1.6454,-0.95)`，坐标是 `(x,z)`。每步把加偏移后的世界位置映射回网格坐标，遇无格停止。见 0x2119d30、0x21b0e4c–0x21b0ec8、0x21b106c–0x21b10bc、0x2398cfc、0x2399658。

扫描遇到顶块是 Car 的格时，将当前累计路径倒序保存到该格 `Blocks[0].MovementPath`，使其从车格指向停车位。赋完车道后用路径副本倒回扫描方向并继续。函数会检查已经设置的路线及本轮分配位置，保留或覆盖按现有路径长度和扫描顺序分支，未使用随时间变化的动态寻路。若同一停车位反向线上有多辆车，扫描收集的较近车格会被纳入后续段；在恢复分支，只把保存记录中「车位坐标、停车位坐标」都匹配的车设到该车道。见 0x21b0a38、0x21b0f38–0x21b1068、0x21b110c、0x21b3a50。

### 排序、入位、道具

- 递归排序的车候选优先于普通同色搬运。沿路线检查前方连续空格，遇全局锁、仍需邻消或有块即停。首辆能走到终点的车优先，否则取可走步数最多的车，相同步数保留先遍历者。每次实际返回、执行的是下一格。评分模拟另有放宽通行的分支，详见 [排序器](SORT_TARGET_SELECTION.md)。见 0x21a2bf4、0x21b54b4、0x21b5bcc、0x21b698c。
- 执行排序把源顶段加入目标块列表、从源移除，再根据 `Block.Animate` 返回时长派发 `Cell.HexAdded`。Car 分支交给 `BlockCar.StartCar`，它每接收一步将 `_distanceCovered` 加 1。表现沿车头方向前行，速度低于配置的 TopSpeed 时逐更新增加 Acceleration，到本次停靠阈值或停车距离阈值后停止。满足停车距离或步数达到 `MovementPath.Count` 时触发停好及 HUD 表现，延时关闭模型、粒子并请求重检。见 0x21a62ec、0x21a6c9c、0x219ecb8、0x219ed90、0x219f46c、0x2118644、0x2118eac、0x2118c08、0x2119b38。
- 停车位监听 `HexAdded`，事件收到的目标格必须就是本格，类型必须为 256。此时 `CellStateChanged(17)` 计入 1 项停车目标，刷新该目标显示后移除本格顶部 Car 色段。此分支没有写 Open 或提升后继，也没有通过正常消除广播。车块逻辑移除与 `BlockCar` 停好表现是分开的调用链。见 0x2119eb4、0x211a220、0x21a905c、0x21bd83c。
- 普通去块道具路径 `Cell.PowerupRemove` 和 Open/下层格 `PowerUpUsed` 的去块分支均在顶块 Car 时直接返回。清除路上的普通块可间接放行；停车位状态没有自身扣 Cost 的命中处理。教程的 `FtueUse` 直接给指定车使用特殊移动目标并按次数区分停止或完成，教程 HUD 回调通知脚本。见 0x21a78d8、0x21a881c、0x211a0f8、0x2118810、0x211963c。
- 存档从当前车格及其路线末格保存两个坐标。若保存扫描时车已处在其停车位坐标，直接 `ItemCollected(17)` 并清该格块表，未继续把它写成待停车记录。恢复按两组坐标重新扫描相同方向，不用保存动画进度。见 0x211a7d0、0x211ae14–0x211aecc、0x211a428、0x211a4ec、0x21b110c。

以上为静态取证。动态配置中的预制件字段、随机选取的结果、同帧并发动画次序和异常关卡数据的实际呈现需要同版本运行证据。附带 [ARM64 指令](SpecialMovementExtra.asm) 与 [方法索引](SpecialMovementExtra.methods.json)。
