# Hexa Sort 6.2.20：手牌生成规则完整性复核

2026-11-25，针对原包 ARM64 `libil2cpp.so`、v39 metadata 复核。本文聚焦生成算法；发牌时机和道具调用链见[核心玩法流程](CORE_GAMEPLAY_FLOW.md)，详细指令见[主分析](README.md)。可核对的字段、关键指令、方法范围和文件指纹见[机器证据](HAND_GENERATION_AUDIT.json)。

结论：原有主流程基本齐全，但不足以直接作为精确复刻规格。主要遗漏是**单空格替换的累计量、最后普通堆留下的参数、替换后不再校验、临时 Easy 耗尽当次的重抽差异，以及预设绕过生成器的副作用**。本次补齐下述静态可确认规则；远程配置和逐次随机序列仍未设备对拍。

## 1. 输入、状态和三种入口

生成器签名是 `GetNext(initial, slotCount, emptyCells, matchTypes)`，不是每槽一个独立的“补牌请求”。

| 输入或状态 | 精确用途 |
|---|---|
| `initial` | 传给第一次 `GetPieces`，决定是否预留同色配对槽；不负责初始化累计量。 |
| `slotCount` | 来自运行时 `TrayItems.Count`。算法不固定为 3；正常三槽是场景配置。配对要求至少还有一个可选的其他槽，不能宣称对任意槽数都安全。 |
| `emptyCells` | 本次发牌采样的 `Cell.IsAvailable` 数；存入 `_emptyCells`，供普通堆 Helper 和单空格分支使用。 |
| `matchTypes` | 本次棋盘的 `TypesWithEmptyNeighbours`；存入 `_emptyCellNeighTypes`，用于智能顶色命中校验。它不是普通堆颜色权重。 |
| `TotalHexCreatedInLevel` | 累计生成块数，关卡初始值来自 `PreCreatedHex`。每个普通堆、配对堆生成后增加；不是发牌轮数，也不是当前棋盘块数。 |
| Easy / Medium | 一次性、持久、临时是不同字段，叠加和清除顺序见第 3、5 节。 |
| `_lastMaxTypes / _lastMaxTypesInStack` | 最近一次普通堆选定的色池与最终候选色上限；单空格分支读取这两个缓存。 |

三种入口要分开：

1. **完整首发预设**：`Tray.SpawnItems(true)` 先尝试 `LevelData.GetPieces(slotCount)`。数量足够且被检查的预设堆都非空时，整组直接装槽；不会调用 `GetNext`。因此这条路径本身不消耗生成器 RNG、不扣临时次数、不做智能校验或单空格替换，也没有通过 `GetPieces` 将预设块数再累加。预设配对索引会另写入 `TutorialIndices`。不能拿预设牌的颜色数、长度倒推随机堆约束。
2. **没有完整预设的首发**：`GetNext(true, ...)`，第一次候选组带配对槽。
3. **自然补牌 / Shuffle / 命中门槛的续玩刷新**：`GetNext(false, ...)`。Shuffle 和该续玩入口额外设置一次性 Easy，普通自然补牌没有这个动作。智能重抽一律改用配对版。

依据：`Tray.SpawnItems` 0x21c84d0–0x21c85c4；预设写配对索引 0x21c8504–0x21c856c；生成器入口 0x21c4d28–0x21c4d50。关卡累计量字段语义另见[关卡参数](../HEXA_LEVEL_PARAMETER_REFERENCE.md)。

## 2. 每个普通堆重新判档

按配置原顺序，找第一条满足 `累计生成量 < ThresholdHexCount(HexCount)` 的记录。**相等时跳过当前记录**。阈值按动态难度倍率缩放后向零截断为整数，不取四舍五入，也不把每组牌固定在开头的档位。

读取该记录的 `MaxTypesInStack`、`MaxTypes`、`Difficulty`。超出全部记录时回到生成器默认值：单堆候选色上限 3、色池 3、基础难度 1；不是一直钉在最后一档。关卡可以提供不同阈值，默认六档见[主分析](README.md#特殊物件移动与关卡阶段)。

动态难度有两路：倍率调整换档线；`GetLevelDifficulty` 的可空返回值调整档内难度。后者影响少空位 Helper，不能把两路合成一个倍率。倍率的多来源选择及 Rolodex 尝试次数见[动态难度](README.md#动态难度如何调整阈值)。

例如累计 28、下一条线是 30，第一堆生成 5 块后累计变 33；第二堆立即按 33 判档。若有配对，先按槽序生成非预留槽，最后才生成配对堆，因此配对堆不会提前推高前面普通堆的档位。

依据：0x21c680c–0x21c683c、0x21c68b8–0x21c692c；缩放与截断 0x21c641c–0x21c6474；普通堆提交累计 0x21c5168–0x21c517c。

## 3. 普通堆的颜色上限与随机抽样

先取档位上限 `K` 和色池大小 `M`，按下列顺序处理：

```text
if emptyCells <= Helper.EmptyTiles:
    difficulty == 0: K = Helper.EasyMaxStack
    difficulty == 1: K = Helper.MidMaxStack
    difficulty == 2: K = Helper.HardMaxStack
    其他 difficulty: K 保持档位值
if EasyTemporaryMode:
    K = 1
else:
    if SpawnEasyOverride: K = 1
    if EasyModeOn and K > 1: K -= 1
    if SpawnMediumOverride and K >= 3: K = 2
K = min(K, M)
_lastMaxTypes = M
_lastMaxTypesInStack = K
```

Helper 是**替换**上限，甚至可以把档位上限增大，然后才叠加 Easy/Medium。阈值取等号；配置未启用、关卡不在范围或配置对象缺失时，空位阈值回退 3。颜色上限 getter 只在配置对象缺失时回退 1/2/3；feature flag 关闭并不直接跳过全部 Helper。这里说的配置对象缺失，不等于组件引用为 null；后者在指令中仍可能抛异常。

普通堆随后这样抽样：

```text
k = RangeInt(1, K + 1)                     // 候选色数，含 K
n = RangeInt(max(MinRandHexPerStack, k), MaxRandHexPerStack)
colors = []; counts = []
最多 100 次，或收集满 k 种后提前结束：
    color = 1 << RangeInt(0, M)
    若未重复：追加 color，追加计数 0
重复 n 次：counts[RangeInt(0, counts.Count)] += 1
按 colors 的抽入顺序，追加各色对应数量的块；计数 0 不输出
```

原包普通块数上下界字段为 2、7，整数上界不含：通常 2–6 块，`k=3` 时 3–6 块。候选色不保证每种至少分到一块，所以实际段数可以小于 `k`。结果是连续色段，底在前、顶在末尾；没有在最后再洗牌，也没有按棋盘占比选色、按关卡目标强行选色或要求本堆能立即消除。

**最多 100 次是去重抽色的尝试上限**，重复抽到同色也消耗尝试和 RNG。达到上限时沿用已经收集的颜色，不承诺一定凑满 `k`；不能改写成无上限重试或一次洗牌取前 k 色。正常有效配置下颜色位值来自色池前 M 位；不要把特殊 Car 位 0x100 当成第九种普通随机色。现有参数验证只要求相关上限为正，不代表能安全处理所有异常大值。

依据：Helper 0x21c6938–0x21c6990；覆盖和缓存 0x21c6994–0x21c69f8；抽样 0x21c69fc–0x21c6c78；100 次边界 0x21c6af4–0x21c6b08。

## 4. 配对组怎样生成

`GetPieces(pairSlot, count)` 的顺序：

1. 清理上一次 `TutorialIndices`。
2. `pairSlot || SpawnEasyOverride` 时先抽一个 `[0,count)` 索引，否则索引为 -1。
3. 按槽序创建结果。**只有 `pairSlot=true` 才跳过抽中的槽**；其他槽逐堆调用普通生成，并立即增加累计块数。
4. 若启用配对，从除预留槽外的槽索引列表均匀选一项，取其普通堆的**末尾顶色**。
5. 用 `GetPieceOfType` 给预留槽生成该色的 3–4 块单色堆，增加累计量，并记录预留槽、来源槽两个索引。

配对只保证一对槽顶色相同，不保证其他槽不同色，也不保证配对后能在棋盘消除。配对堆不调用普通抽色、Helper 或重新判档；其 3–4 块来自独立字段 3、5，不等于普通 Easy 的 2–6 块。

仅开启一次性 Easy 的普通刷新也会抽预留索引，随后**仍生成所有普通槽**。这个没有改变槽内容的随机调用必须保留，否则后面全部随机序列会错位。

依据：0x21c5074–0x21c50ec、0x21c5138–0x21c518c、0x21c51d0–0x21c5300、0x21c6e00–0x21c6e38。

## 5. 智能校验、临时次数和重抽

严格执行：**先生成首组 → 再扣临时次数 → 再决定是否校验**。

| 状态 | 校验决定 |
|---|---|
| 临时 Easy 开着，扣后次数仍 >0 | 先令 `validate=true`。 |
| 临时 Easy 开着，扣后次数 <=0 | 关闭临时模式，令 `validate=false`。首组已经按扣前状态生成。 |
| 一次性 Easy 且智能功能开，距上次刷新严格小于窗口 | 用 `RangeInt(0,100) < probability` **覆盖**上述决定；不是逻辑 OR，抽不中会关掉本次校验。 |
| 同上，但达到或超过窗口 | 不做概率抽样，保留临时模式给出的决定。 |
| 没有一次性 Easy，或智能功能关 | 不进入上述计时/概率分支；仍可因临时 Easy 校验。 |

只有进入“一次性 Easy 且智能功能开”分支才更新 `_lastRefreshTime`，窗口内外都更新。包内默认智能配置为开启、60 秒、100%；窗口不是“广告观看后 60 秒”，也不是自然发牌共用的 60 秒保证。

`SpawningAlgorithm.Init` 本身清持久/临时 Easy 和临时次数，但没有写 `_lastRefreshTime`。不能据此假定每关智能窗口自动从 0 重置；是否因对象重建或其他入口改变，还要结合运行时生命周期。`ConfigureLevelParameters` 是初始化参数选择，实际普通堆仍会重新判档、应用 Helper 和一次性覆盖，不能用初始化缓存代替之后每堆的有效参数。

`ValidatePiecesWithGrid` 只判断**任一候选堆顶色**是否在 `matchTypes`。集合 null 或空直接通过；不看埋在下面的颜色，不模拟落点、连锁或必败。非空集合下，空候选组不通过；遇到 null/空候选堆也不能自行等价成“跳过”。

每次校验失败就置 `SmartRefreshUsed=true`，重新调用 `GetPieces(true,count)`。最多 **5 次重抽，连首组最多 6 组**；第五次重抽出来的组直接交付，不再检验。所有被弃的普通堆和配对堆都已增加累计量，后续重抽继续从新累计量选档。每次 `GetNext` 只扣一次临时计数，重抽不额外扣。

需要单独覆盖的叠加边界：临时 Easy 剩 1 次且又遇 Shuffle。首组仍单色，扣完后临时模式关闭；若刷新概率开启校验而首组失败，重抽普通堆仍因一次性 Easy 保持单色。若没有一次性 Easy，就不会仅因刚耗尽的临时次数而开始这次重抽。不要把“第 N 次仍单色”扩大成所有后续调用都继续临时 Easy。

`SmartRefreshUsed` 表示本次**确实重抽过**，不是“开启过校验”。首组校验成功时仍为 false，后面仍可走单空格替换。`DidGetPowerupPieces` 在单空格检查前清零。`SpawnEasyOverride` 到正常返回末尾才清掉；Medium 不在这里消费。完整预设绕过 `GetNext`，不会执行这些清理；异常中止也不能假设已经走过返回末尾。

依据：0x21c4d50–0x21c4e3c、0x21c4e70–0x21c4f54、0x21c5334–0x21c5450。

## 6. 单空格道具手牌：最后一次覆盖

仅当本次输入 `emptyCells == 1`、未发生智能重抽、配置功能开启时调用 `GetPowerupPieces`。它在普通生成和校验之后运行。

1. 找到首个可放置且顶色为 0 的格。用**最后一个普通堆留下的 `_lastMaxTypes`**，从八色固定数组取前 M 色。这个选择器与外层 `Cell.IsAvailable` 计数的表达式不同，不能无条件认为所有异常状态下都找得到。
2. 对这些颜色统计该空格可放邻居的顶部同色段块数，排除 0 和 Car。过滤为块数 <8；A 为 0 块颜色，B 为 1–4 块颜色，5–7 块不进入 A/B。A 为空或 A+B 少于 2 种则保留原牌。
3. 只对 A 重新统计全盘：每个可放格顶色贡献 1 格，取格数 >0 的颜色，按格数降序、随机整数键 `[0,100)` 升序，再取至多两色为短名单 S。不是按全盘块数排名，也不是将全盘颜色直接替换为邻域匹配色。
4. 若 S+B 少于 2 种，保留原组。
5. B 非空时，**第一个输出槽**构造一次短堆。最后普通堆缓存的 `_lastMaxTypesInStack >=2` 时为 `S[0]×(2–3)` 加 `B[0]×(2–3)`，总长 4–6，顶为 B；缓存上限 <2 时只造 `B[0]×(2–3)`。B 沿已有枚举顺序取第一项，没有另做最优评分或随机挑 B。
6. 其余槽按 S 的顺序循环，各造 7–8 块单色堆；S 没有可用索引时保留对应原槽。B 为空时从第一个槽就走这个循环。

这条分支另有三个必须明确的边界：

- **累计量不按替换后的长堆重算。** 原候选组生成时已计入累计量；`GetPowerupPieces` 内构造短/长堆没有再次调用普通生成或配对生成，也没有相应的累计值增加。最终可见 7–8 块不代表累计多加了 7–8。下一组沿用此前候选量；不能以最终牌面总块数替代原计数。
- **不重新判档、不重新套普通上限、不重新校验。** M/K 来自最后一次普通堆，而非组开始时，也非补算配对堆后的档位。替换后直接回 `GetNext` 尾部，不再经过顶色命中或落子模拟；首组通过智能校验不代表最后交付组又通过了一次校验。
- **不是所有缺候选都安全回退。** S 空但 B 至少两种时，数量检查仍可通过；缓存 K>=2 的短堆直接访问 `S[0]`，存在越界路径。输出个数检查只在末尾比较 `< 输入个数`，并不要求严格相等。颜色 0 的异常分支会在已追加构造堆后再追加原槽，不能自行改写成“替换失败总是返回正常三槽”。正常八色配置不会把 0 当作候选色，这些是异常输入边界。

`DidGetPowerupPieces` 只在长堆构造路径置真，不能把它等同于“调用过 GetPowerupPieces”或“任意槽变了”。正常返回后它没有回写候选累计量。配对索引也没有在这条路径重新计算，观察该索引时要结合最终输出。

依据：选色 0x21c6e44–0x21c7604；分类/短名单 0x21c57d8–0x21c6030；缓存上限/短堆 0x21c60c0–0x21c61c8；长堆/原槽回退 0x21c61d4–0x21c62ec；长度检查 0x21c62f0–0x21c6368；返回后直接清一次性标志 0x21c4f48–0x21c4f54。

## 7. 生成计数对照

| 分支 | 推进累计块数 | 扣临时次数 | 重新判普通档位 |
|---|---|---|---|
| 完整预设首发 | 本路径没有增加 | 否 | 否 |
| 每个普通随机堆 | 增加该堆长度 | `GetNext` 首组结束后统一扣一次 | 每堆都判 |
| 同色配对堆 | 增加配对堆长度 | 不另扣 | 否 |
| 智能重抽 | 每个新普通堆、配对堆继续增加，旧候选不退回 | 不另扣 | 新普通堆逐个判 |
| 单空格短/长堆替换 | 不另增、不扣回原候选量 | 不另扣 | 否，读最后普通堆缓存 |
| 消费旧牌或吸走旧块 | 不减少 | 没有生成就不扣 | 没有生成就不判 |

## 8. 完整性与验证边界

对拍应至少包含这些有区分力的输入：

| 输入边界 | 预期核对点 |
|---|---|
| 完整首发预设 / 缺一堆预设 | 前者绕过 GetNext；后者整组改为随机首发，不拼补预设。 |
| 累计恰等于阈值 / 首堆跨线 | 到线选下一档；同一组后续普通堆可以换档。 |
| 累计超过最后一条阈值 | 回默认 3/3、基础难度 1，随后仍受覆盖规则影响。 |
| Helper 阈值 3，空位为 3 / 4 | 前者替换颜色上限，后者不替换。 |
| 抽到 k=3，但有颜色计数为 0 | 长度仍按 n，实际颜色数可少于 3，不强行补色。 |
| 一次性 Easy，initial=false | 多抽一个槽索引，却不预留配对槽。 |
| 临时次数 1 / 2，且没有一次性 Easy | 两者首组都单色；扣后前者不因临时模式校验，后者会。 |
| 临时次数仍有效，刷新窗口内且概率 0 | 刷新概率覆盖 true，跳过本次校验。 |
| 距上次刷新恰等于窗口 | 不进行概率抽取，但该刷新分支仍更新时间。 |
| 连续校验失败 | 累计最多生成六组；第五次重抽直接交付，旧候选量不扣回。 |
| 一个空位、首组校验成功、道具分支开启 | SmartRefreshUsed 仍 false，仍可替换；最终组不再校验。 |
| 候选后累计跨档，再走单空格长堆 | 用最后普通堆缓存 M/K；长堆不再次推进累计量或重新判档。 |

本次已逐项核对：首发预设与随机首发、逐堆跨档和超档默认、动态阈值与档内难度、Helper 边界、三类 Easy 与 Medium 顺序、候选色去重上限和零计数颜色、配对与多余随机索引、智能窗口/概率覆盖、最多五次重抽、单空格分类/排名/缓存/替换/计数、交付后的标志与槽位兜底。`HalfHexProbability` 没有出现在已核对的两处阈值消费中，仍不据此宣布全局没有其他用途。
